# Экспорт FCPXML в DaVinci Resolve

Кнопка **«Сгенерировать Time Line»** сохраняет FCPXML 1.9 в корне проекта
на Google Drive или в локальной папке. После успешного сохранения появляется
**«Time Line готов»**. Браузер не скачивает XML.

## Пути к медиа

Основной режим — абсолютные ссылки `file:///…`. При локальном запуске путь
автоматически берётся из папки проекта. Если Resolve работает на другом
компьютере, укажите путь к проекту именно на том компьютере.

Для Google Drive/Render введите локальный путь к папке на компьютере с Resolve,
например `/Users/editor/Projects/Мой проект`. Внутри должны находиться папки
`images` и `audio`; файлы Drive должны быть доступны локально.
Путь запоминается в браузере для данного проекта. Windows и UNC также
поддерживаются; пробелы, русский текст, %, # и ? кодируются в URL.

Поле влияет только на ссылки в XML, не на место сохранения проекта на сервере.
Путь Render автоматически не подставляется. Если для облачного проекта путь
на компьютере не указан, абсолютный экспорт не выполняется.

Есть дополнительный режим относительных путей `images/…` и `audio/…`.
Он переносим, но Resolve может потребовать вручную указать папку с медиа.
[Спецификация Apple](https://developer.apple.com/documentation/professional-video-applications/media-rep)
допускает и абсолютные, и относительные URL. Это не гарантия одинакового поведения
всех импортёров Resolve. Для случая, где относительные ссылки не подхватываются,
предусмотрены абсолютные ссылки на реальную папку компьютера с Resolve.

## Зачем появились файлы still_…

Resolve может объединить `frame_1_1.jpg`, `frame_1_2.jpg` в последовательность
`frame_1_[1-2].jpg`. Поэтому экспорт использует отдельные побайтовые копии
с буквенными именами `still_<буквы>.jpg`, PNG или WebP в `images`.
Имя определяется содержимым. Повторный экспорт того же изображения использует
тот же файл; новые копии с суффиксами (1), (2) не создаются.

Исходники не переименовываются и не удаляются. Имена клипов на таймлайне
остаются `frame_1_1.jpg` и т. д. После изменения изображения появляется новая
экспортная копия. Старые копии автоматически не удаляются: на них могут ссылаться
предыдущие таймлайны.

Для старого локального проекта без `projectPath` создаётся папка
`PROJECTS_ROOT/project_<id>` (по умолчанию `server/uploads/projects/project_<id>`
при запуске из server). В MongoDB сохраняется путь; исходные storageKey остаются
прежними. Старые MP3 копируются под именами `audio/audio_block_1.mp3`.
При конфликте содержимого существующий файл не перезаписывается.

## MP3 и обрезка краёв

MP3 анализируется через [music-metadata](https://github.com/Borewit/music-metadata)
в Node.js без ffmpeg. При генерации сохраняется `audioDurationSec`. Для старых
MP3 длительность определяется чтением из локального хранилища или Drive
и записывается в MongoDB. Если анализ доступного файла не удался, используется
оценка по тексту с предупреждением. Недоступный или пустой файл блокирует экспорт.

Обрезка по умолчанию выключена. Два режима:

- **По числу символов слова или фразы.** Можно ввести любой текст. Наличие его
  в озвучке не проверяется. Число символов без внешних пробелов определяет
  одинаковую обрезку в начале и конце каждого блока:
  `секунды края = длительность MP3 × длина введённого текста / длина текста блока`.
  «Да» даёт вдвое меньшую обрезку, чем «Стоп». Расчёт приблизительный,
  это не распознавание речи; паузы и скорость произнесения могут отличаться.
- **По секундам.** Начало и конец задаются отдельно и применяются ко всем блокам.
  Каждое значение — от 0 до 60 секунд; сумма должна быть меньше длительности
  каждого блока.

Интерфейс показывает обрезку и оставшееся звучание каждого блока.
В XML меняются только start, offset и duration подключённого аудиоклипа.
Блок 10 секунд с обрезкой 0,5 секунды слева и 0,7 справа звучит с 0,5 до 9,3
секунды. Оставшаяся речь, изображения и следующий блок сохраняют позиции.
На месте краёв остаются пустые участки аудиодорожки. Исходный MP3 не изменяется;
его края можно восстановить в Resolve.

## Таймлайн, анимации, маркеры и переходы

Изображения — asset-clip непосредственно в spine. Аудио прикреплено к первому
изображению блока как connected clip на lane -1. Расчёты используют целочисленные
доли 1/35 280 000 секунды. Кадры распределяются по доле символов scriptText,
последний получает остаток. Длительность блока соответствует MP3, ошибки
округления до видеокадров между блоками не накапливаются. FPS: 24/25/30.

Перенесены Zoom In/Out, Pan Left/Right/Up/Down из Telegram-бота. Последний ключ
находится за один видеокадр до конца клипа. Необязательные animation и marker
редактируются в настройках кадра без изменения prompt, referenceIds, frameId
и актуальности изображения. Маркеры: Voiceover Text, Start Time,
Animation Instruction и пользовательский маркер, если они заданы.

Переходы по умолчанию выключены. При включении они создаются **на всех стыках**,
включая границы аудиоблоков, а также в начале и конце таймлайна.
Переходы через чёрный накладываются вокруг стыков; изображения и аудио
не сдвигаются. Половина внутреннего перехода ограничена четвертью длительности
обоих соседних клипов. Краевые переходы ограничены четвертью первого/последнего
клипа. Время округляется вниз до сетки FPS; слишком короткий переход пропускается.
Переходы не перекрывают друг друга и не удлиняют таймлайн.

## Ручная проверка

1. Перезапустить сервер, обновить страницу. Проверить готовность медиа.
2. Выбрать абсолютные пути. Проверить, что папка доступна на компьютере
   с Resolve и содержит images со still-копиями и audio с MP3.
3. Включить обрезку по символам. Ввести «Да», затем «Стоп»: значения должны
   пересчитаться вдвое. При необходимости подобрать обрезку в секундах.
4. Нажать «Сгенерировать Time Line». XML должен появиться в корне проекта;
   браузер ничего не скачивает, интерфейс показывает «Time Line готов».
5. В пустом проекте Resolve открыть File → Import → Timeline, выбрать XML
   из папки проекта. Проверить автоматическое подключение изображений и MP3.
6. Каждый кадр должен быть отдельной картинкой без имени последовательности
   в квадратных скобках. Проверить Zoom/Pan и маркеры.
7. Сравнить варианты без переходов и с ними. Проверить внутренние стыки,
   границы блоков, начало и конец. Позиции медиа и общая длительность совпадают.
8. Сравнить обрезку и исходный вариант: у аудио изменились только края.
   Прослушать каждый край, особенно при приблизительном расчёте по символам.
9. Повторить на 24/25/30 FPS. На тестовой копии временно переместить MP3 или
   изображение: после обновления страницы экспорт должен стать недоступен.

## Границы автоматической проверки

Тесты проверяют CBR/VBR MP3, расчёты, XML, пути, локальные копии, маршруты
с подменой MongoDB и передачу копий в шлюз Drive. Импорт текущего варианта
в установленном Resolve и работа с живым Drive требуют ручной проверки.
Resolve может округлять видеомонтаж до сетки FPS. Импорт переходов и поддержку
WebP нужно проверить в используемой версии. Автоконвертации изображений нет.

На изображение требуется минимум один видеокадр времени. Временные метки речи
не сохраняются, точные границы слов не определяются. Интерпретация encoder
delay/padding может различаться у проигрывателей. Если MP3 заменили вручную
вне WebApp, сохранив ключ и запись БД, длительность автоматически не
пересчитывается. Проверка больших проектов читает медиа последовательно
и может занимать время, особенно на Drive.

## Проверка загрузки новой версии на Render

Файлы `shared/davinciAudioTrim.js` и `shared/davinciMediaPaths.js` нужны и серверу,
и клиенту. Они должны входить в коммит вместе с изменениями в server и client.
Локальная сборка может проходить с незакоммиченными файлами, которых на Render нет.
Для проверки состава следующего коммита используйте `git diff --cached --stat`.

После успешного нового деплоя `/api/health` возвращает `davinciExportVersion: 2`
и `buildCommit` — SHA из `RENDER_GIT_COMMIT` (при локальном запуске — null).
Это публичный идентификатор версии, а не секрет. Если этих полей нет, отвечает
старая версия сервера. При неудачном деплое Render может продолжать обслуживать
предыдущую версию; обычный Restart Service не исправляет отсутствующие файлы.
Нужно включить их в новый коммит, отправить его в подключённую ветку и дождаться
успешного Deploy latest commit. При ошибке сборки смотреть Build/Deploy Logs,
а не только HTTP-запросы запущенной старой версии.
